# AGENTS.md

## 1. О проекте

Task Tracker — учебный backend-проект для практики Clean Architecture, EF Core и тестирования.
Solution: `src/Backend/PS.TaskTracker/PS.TaskTracker.slnx`.
Пять слоёв: `PS.TaskTracker.Domain`, `PS.TaskTracker.Common`, `PS.TaskTracker.Application`, `PS.TaskTracker.Infrastructure`, `PS.TaskTracker.API`.
Направление зависимостей — от API к Domain, обратных ссылок нет.

## 2. Роль агента

Пиши код, тесты и документацию по явной задаче из промпта.
Следуй архитектурным правилам из раздела 7 и соглашениям из раздела 6.
Не принимай архитектурные решения в одиночку: изменения зависимостей между слоями, состав слоёв и выбор технологий согласуй с человеком до реализации.
Не расширяй задачу за пределы промпта.

## 4. Правила работы

Перед задачей читай `AGENTS.md` и релевантные документы из `docs/`.
Работай итерациями: одна задача — один законченный фрагмент.
Не расширяй задачу за пределы промпта.
Если промпт противоречит документации — сообщи и остановись, не выбирай молча.
Если обнаружено расхождение между кодом и документацией — сообщи.

## 5. Чего не делать без явной команды

Не выполняй `git add`, `git commit`, `git push`, `git reset`, `git rebase`, `git checkout` и прочие изменяющие git-операции.
Не выполняй `dotnet restore`, `dotnet build`, `dotnet test`, кроме случаев, когда промпт явно просит проверить сборку.
Не создавай и не удаляй файлы за пределами задачи.
Не добавляй NuGet-пакеты без указания в промпте.
Не меняй архитектурные решения (ссылки между проектами, состав слоёв) без обсуждения.
Не добавляй MediatR, AutoMapper, CQRS-фреймворки, микросервисы и прочие абстракции «на будущее».

## 6. Соглашения по коду

Язык документации и комментариев — русский. Идентификаторы в коде — английский.
C# latest, `Nullable=enable`, `ImplicitUsings=enable` заданы централизованно в `Directory.Build.props` — в `.csproj` не дублируй.
Версии NuGet-пакетов задавай только через `Directory.Packages.props` (Central Package Management) — в `.csproj` версии не указывай.
Стиль кода — по `.editorconfig`. `TreatWarningsAsErrors=true`, предупреждения ломают сборку.
Namespace — file-scoped.
Один публичный тип — один файл.

## 7. Архитектурные правила

`Domain` — ни от кого не зависит. Никаких ссылок на EF Core, ASP.NET Core, инфраструктуру.
`Common` — ни от кого не зависит.
`Application` → `Domain`, `Common`.
`Infrastructure` → `Application`, `Domain`, `Common`.
`API` → `Application`, `Infrastructure`, `Common`.
`Infrastructure` не течёт в `Application`: интерфейсы репозиториев живут в `Application`, реализации — в `Infrastructure`.

## 8. Формат отчёта после задачи

Что сделано (список файлов).
Diff или содержимое изменённых файлов.
Результат сборки/тестов, если применимо.
Замечания и отклонения от промпта.
Явная строка подтверждения: «Задача завершена. Жду следующего промпта.»

## 9. Обновление документации

Изменение архитектуры → обнови `docs/ARCHITECTURE.md` и `docs/DECISIONS.md`.
Изменение бизнес-правил → `docs/DOMAIN.md`.
Изменение функциональности → `docs/SPEC.md`.
Прогресс по этапам → `docs/ROADMAP.md`.
Обновление документации — часть задачи, а не отдельная задача, если промпт не говорит иначе.
